# 沙漠精灵 Oasis · 流沙卡牌冒险

一个以**沙漠蜻蜓 Oasis** 为主角的网页 2D 宝可梦卡牌 roguelike。
从「流沙之海」出发，穿过「赤岩峡谷」，走到「夜砂墓原」——看看你能走多远。

> 非商业同人练习作品。宝可梦精灵图来自 [PMDCollab/SpriteCollab](https://github.com/PMDCollab/SpriteCollab)，
> 界面图标 / 面板 / 音效 / 粒子来自工作区里的 Kenney 素材包（CC0），
> BGM 来自 [音楽の卵 (ontama-m.com)](https://ontama-m.com/)（免费使用、可商用、无需署名）。
> 宝可梦译名以 [52poke 神奇宝贝百科](https://wiki.52poke.com/wiki/%E4%B8%BB%E9%A1%B5) 为准。

## 怎么跑起来

### 方式一：双击 `play.cmd`（推荐，音效 + BGM 都能听到）

在文件管理器里**双击项目根目录的 `play.cmd`**：它会自己切到项目目录、启动本地服务器、
把地址打印出来并自动打开浏览器。命令窗口要一直开着，关掉窗口 = 关掉服务器。

它做了这些「防呆」：
- 脚本内部先 `cd /d "%~dp0"`，所以**在哪个目录双击都能跑**；
- 默认端口 5123，**被占用会自动往后找**（5124、5125…）并把真实地址打印出来；
- 没装 Node.js 会直接告诉你（也可以改用方式二直接双击 `oasis-game.html`）；
- 启动时顺手检查 `index.html` / `src/main.js` / `sprites.json` / `bgm` 在不在，缺了会列出来。

### 方式一（命令行版）

```powershell
node tools/serve.mjs            # 位置随便，脚本按自己所在目录找项目根
node tools/serve.mjs 6000       # 指定端口
node tools/serve.mjs --no-open  # 不自动开浏览器
```

> ⚠️ 别在家目录里敲 `node tools/serve.mjs`（例如 `C:\Users\你>`）——那会报
> `Cannot find module 'C:\Users\你\tools\serve.mjs'`，因为 **shell 的当前目录不对**，
> 跟脚本无关。要么先 `cd` 到项目目录，要么用上面的一键 `play.cmd`，要么写脚本的完整路径。

也可以直接用任意静态服务器（`npx serve`、`python -m http.server` 之类）。

### 方式二：双击直接玩（最省事，但没有声音）

直接双击 **`oasis-game.html`** 就能玩。这个文件是打包产物：源码、CSS、图标素材、精灵图全部内联在一个 HTML 里，
不依赖 ES module、不依赖 fetch，所以在 `file://` 下也能正常跑。

> ⚠️ 不要双击 `index.html`——它是**开发用入口**，用 `file://` 打开时浏览器会以 CORS 政策拦掉 `src/main.js`，
> 结果就是「除了背景什么都没有」。

> 🔇 `file://` 下浏览器会拦掉**所有**本地音频请求（fetch / XHR / `<audio>` 全部失败，实测过），
> 所以音效与 BGM 会静默失效。BGM 一共 60 多 MB，内联进单文件会让它膨胀得离谱，所以没这么做。
> **想听声音请用方式一。**

### 改完源码后要重新打包

```powershell
node tools/bundle.mjs     # 重新生成 oasis-game.html
```

调试用的直达链接（只在方式一下可用）：

```
http://127.0.0.1:5123/?scene=battle     # 直接进一场战斗
http://127.0.0.1:5123/?scene=boss       # 直接打首领
http://127.0.0.1:5123/?scene=shop       # 直接进商店
```
`scene` 支持：`map / battle / elite / boss / event / chest / shop / rest / reward / deck / gameover / victory`。

遭遇演出（从地图踏进战斗的那段过场）默认**只在真的从地图走过去时**才放 ——
`?scene=` 和其余诊断脚本都是「直接进战斗」，中间插 1.7 秒过场会把它们全打乱，
所以那些入口自动跳过。想强行打开 / 关掉：

```
http://127.0.0.1:5123/?enc=1      # 任何入口都放（遭遇演出自己的诊断用它）
http://127.0.0.1:5123/?enc=0      # 完全不放
```

## 玩法

### 一局的结构
- 一次完整的一局是 **6 章**：流沙之海 → 赤岩峡谷 → 藤蔓密林 → 潮汐盐海 → 风蚀峭壁 → 夜砂墓原。
- 每一章是一张**分叉地图**，从下往上走，每步在 2~3 个节点里选一个。
  每张地图的**行数与节点配比都不一样**（写在 `content/biomes.json` 的 `shape` 里）：
  密林事件多、盐海商店/宝箱多、峭壁战斗与精英多、终章又长又狠。
- 节点类型：**野生宝可梦 / 强敌 / 未知事件 / 宝箱 / 商队 / 营地 / 章节首领**。
  商队与营地按地图换叫法（第 1 章「沙漠商队 / 绿洲营地」、第 4 章「海市商船 / 礁石营地」、第 6 章「夜市灯摊 / 守夜火堆」…）。
- 敌人共 **83 种**（其中野生小怪 45 种），物种取材跨 **Gen 3~8**：沙漠有黑眼鳄 / 沙河马 / 沙丘娃，密林有木守宫 / 藤藤蛇 / 伪螳草，盐海有弱丁鱼 / 好坏星，峭壁有小箭雀 / 滚滚蝙蝠 / 小陨星，墓原有烛光灵 / 哭哭面具 / 独剑鞘……
- 走到首领并击败它 → 进入下一章。六章都走完 = 通关（终章首领固定是「基格尔德」）。
- **HP 在战斗之间保留**；HP 降到 0 就结束这一局，结算界面会告诉你走了多少步、击败了多少对手。

### 属性
| 属性 | 作用 |
| --- | --- |
| 攻击 ATK | 伤害的基本值 |
| 防御 DF | 减伤：受到伤害 `× 60 / (60 + DF)` |
| 血量 HP | 归零即失败，战斗间保留 |
| 敏捷 AGI | 决定每回合 **AP**、**抽牌数**、**出牌上限**（这三项在战斗底栏和卡组页都直接写着数值） |
| 幸运 LUK | 暴击率、闪避率 |
| 幸运 LUK | 暴击率、闪避率 |

派生公式：

```
AP        = min(8, 2 + 敏捷 / 2)
抽牌      = min(8, 3 + 敏捷 / 5)
出牌上限  = min(9, 3 + 敏捷 / 2)
暴击率%   = 幸运 × 100 / (100 + 幸运 × 2.4)
闪避率%   = min(45, 幸运 × 100 / (100 + 幸运 × 3.2))
```

### 战斗
- 攻击时：`伤害 =（攻击方 ATK + 卡牌威力）× 60 / (60 + 防守方 DF)`，最低 1 点；先扣**护盾**。
- 每回合 **AP 回满**、抽牌补到上限；**打出去的牌进弃牌区**，
  标着**销毁**的卡一场战斗只能用一次（进销毁区，永远不洗回来）。
- **牌的流向**（用户点名的规则）：打出去的牌 → `弃牌区`；**牌堆抽空、还要再抽的时候**
  `弃牌区` 才洗回牌堆。所以牌组薄的时候同一张牌一轮里能被打上好几次
  （打出去 → 牌堆抽空 → 洗回来 → 又抽到手），但不管怎么轮换，
  一回合最多打 `出牌上限`（`3 + 敏捷 ÷ 2`，上限 9）张，不会失控。
  - 旧版是「打出去塞回牌堆**最底端**」，玩家很难预判下一张抽到什么；
  - 旧版还有一个更难受的地方：抽上来的牌超过手牌上限时，**多出来的会被静默丢进弃牌堆** ——
    一回合结束手里剩 5 张、下回合又抽 5 张，只有 1 张放得下，另外 4 张无声无息地没了。
    玩家的感受就是「我什么都没干，牌怎么莫名其妙进了弃牌区」。
    现在**抽到手牌满为止**，剩下的留在牌堆顶，一张都不会凭空消失。
- **每回合有出牌次数上限**：`出牌上限 = 3 + 敏捷 ÷ 2`（上限 9）。敏捷 10 时是 8 张/回合，
  所以再花哨的连招也只能打这么多张。
- 抽牌数通常大于手牌上限，但**抽到手牌满为止** —— 放不下的留在牌堆顶，不会凭空消失（见上面「牌的流向」）。
- **闪避会连附加效果一起挡掉**：带伤害的牌（咬碎、火焰牙、泼沙…）如果攻击被完全闪开，它附带的降防御 / 中毒 / 灼伤也**不生效**；纯变化牌（刺耳声这种没有伤害的）不受影响。
- 状态：中毒（回合开始掉层数点，然后层数 -1）、灼伤（每回合掉，层数不减）、
  虚弱（攻击 -25%，**挂上之后那一方打完整整一个回合才掉 1 层**）。
- **反制手段一定拿得到**：卡组里一张回血牌都没有时，战斗奖励里必出一张回血牌；
  第 2 章起，卡组里没有解状态/解削弱的牌时，奖励里必出一张（只替换最后一个选项）。
  「白雾」现在**同时清除属性下降与负面状态**（灼伤、中毒、虚弱、流血），
  每位商人也都至少备一瓶药 —— 以前唯一能清灼伤的「焕然一新」是 rare 还带销毁，一局很可能根本见不到。
- **动画**：每回合抽到的牌从屏幕下方滑入（非线性缓动，一张接一张，不是一起蹦出来）；
  带「销毁」的牌打出去后会**碎成碎片飞散淡出**，表示这张牌真的没了；
  打牌消耗 AP 时，对应的行动点会**先弹一下再熄灭**、数字滚下去，并飘出一个「-N」。
- **回合切换立绘**：光带扫过、大字幕上的「第 N 回合」停稳之后，
  对应一侧的**正 / 背面立绘**会**由大变小**落到**回合数左边 / 右边**（我方在左、敌方在右）——
  立绘就在那条横扫屏幕的**回合光带上**，不是别的地方。
  素材是 Generation 9 Pack 的官方风格图（`assets/gen9/`），
  我方用**背面**、敌方用**正面**（和正作一样：自己的宝可梦给看后背）。
  **同一套立绘也用在「遭遇演出」里**（从地图踏进战斗的那段过场，见 `src/ui/encounter.js`）。
  几条设计上的硬约束（都有断言守着，见 `tools/diag-turnart.js`）：
  - **过场不挡操作**：`turnIntro()` 把浮层挂上去就返回，事件流不等它演完 ——
    抽牌演完、手牌一解锁，光带还在屏幕上飘着，**玩家已经可以出牌了**；
  - 光带因此把停留时间从 1250ms 拉长到了 **2600ms**（`PACE.turnSweep`）：
    不挡操作了，停久一点才有时间看清回合数和立绘；
  - 两侧立绘位**等宽**，所以回合数字幕永远在光带正中，加一张图不会把它顶偏；
  - 缩放原点是「靠着回合数的那条边」，于是它一开始是**盖住回合数**的一大团、
    收拢之后停在旁边 —— 不是从旁边「长出来」；
  - 立绘位做了 `skewX(12deg)` **反向斜切**（光带整体是 -12deg）——
    宝可梦歪着站会很像坏图，但斜切的光带是这套 UI 的招牌样子；
  - 时长跟「设置 → 战斗演出速度」联动（快档光带 1430ms、立绘 341ms）；
  - 素材缺失（新物种还没导图）时**安静跳过**，不留破图。
  想调就改 `src/ui/battle-view.js` 的 `PACE.turnSweep / turnArtLead / turnArtIn / turnArtHold / turnArtOut`，
  起始倍数在 `src/core/gen9.js` 的 `ART_FROM_SCALE`，立绘大小在 `style.css` 的 `--tart-h`。
- **遭遇演出**（`src/ui/encounter.js`，从地图踏进战斗之间那 ~1.9 秒）：
  黑幕**从第一帧起就盖住整个屏幕**，我方**背面立绘**从右边非线性划到**左下**、
  敌人的**正面立绘**从左滑到**右上**（两只错开，不在同一条水平线上）；
  背景是一组主题色横线（主线 + 上下各两条更细更暗的）**跟着敌人的正面图**铺过来
  （整组右端逐帧贴着它的中线，纵向以它的中腰为基准上下铺开）；
  双双停留一小会，然后一起滑出屏幕、进战斗。
  右下角是名牌：**霓虹灯档位在下、大号名字压在它上面，两者都居右**（共享同一条右边缘）。
  霓虹灯 = 档位词（野生 / 较强 / 精英 / 首领）用**超大**空心字横向错开叠 **4 份**、半透明
  （空心 = 字身透明 + -webkit-text-stroke 描边）。它是 .encounter 的**直接子节点**、
  z-index 高过两只立绘 —— 用户要求「叠在所有元素（除了背景）之上」，
  塞在立绘那一组里是做不到的（那样层级永远低于 z-index 更高的我方立绘）。
  三个附带的设计点：
  - 用的是**回合立绘**（和上面那套同一份素材），不是战斗场地上的 PMD 行走图；
  - 停留那一小会**不是纯装饰**：战斗要用的 26 个音效（约 2.9 MB）和这一场的 BGM
    在这段时间里**预载 + 解码**完 —— 否则每个音效第一次响都要先等一次下载 + 解码，
    听感上就是「点下第一张卡，挥剑声慢半拍」（线上实测冷启动 2865ms，本地 39ms）；
  - 只在**真的从地图走过去撞见**的战斗里出现（`game.battleEntry === 'map'`）：
    `?scene=` 与其余诊断脚本都是直接进战斗，中间插 1.7 秒过场会把它们全打乱。
    想强行开关用 `?enc=1` / `?enc=0`。
- **敏捷到底影响什么，界面上直接写着**：`敏捷` 管的是**一回合的三项预算** ——
  行动点 `2 + 敏捷÷2`（上限 8）、每回合抽牌 `3 + 敏捷÷5`（上限 8）、
  出牌上限 `3 + 敏捷÷2`（上限 9）。这三项以前只有悬停里一句「都看它」，
  玩家只会遇到「牌是亮的却打不出去」。现在：
  - 战斗底栏有 **`出牌 x/y`**（用完了变红）和 **`抽牌 n`** 两个胶囊，每次出牌当场递减；
  - 顶部 HUD 的「敏」胶囊**悬停会弹出**三项的具体数值与公式
    （以前挂的是原生 `title`，要等一两秒才出来，等于看不见）；
  - 卡组页最左边多了「**每回合的预算（敏捷 N）**」卡片，不悬停也看得到。
- 护盾在持有者自己的回合开始时清空，所以它是「撑过这一轮」的资源。
- **属性下降有下限**：攻击 / 防御 / 敏捷最多被削到**基础值的一半**
  （`balance.debuffFloorPct`）。因为削弱是整场战斗永久叠加的，敌人一副牌里又不止一张，
  不设下限的话防御会被磨成负数 —— 那等于没穿甲，打小怪也变成站着挨打。
- **削弱有解法**：「白雾」（1 费，清掉自己所有属性下降 + 护盾）和
  「焕然一新」（0 费，连负面状态一起清，销毁）—— 敌人越到后面越想用削弱拖你，这两张是应对手段。
- **敌人有专用的弱招**（`content/cards.json` 里标了 `enemyOnly`，玩家抽卡池永远不会出现）：
  抓挠 / 扬沙 / 缩壳 / 低吼 / 瞪眼。小怪只能用这些 + 最基础的普攻，
  不会再拿到「0 费抽 1」「攻击 +4」这类玩家级别的价值牌。
- 中间那个小胶囊是**对手的威胁预估**：拿对手整副牌 + 它下回合的行动点 / 出牌数，
  用它自己那套 AI 评分模拟一遍，给出「下回合**最多**约多少伤害（最狠的是哪一招）」——
  是上界（它真抽到什么牌随机），够疼会变黄、能把你打倒会变红闪动。
  它下回合行动时胶囊会变成「对手正在行动……」。
- **简单特效**（全部复用 `assets/img/fx/` 里已有的贴图，没有额外画素材）：
  - 用强化 / 变化类技能（变硬、龙之舞、剑舞、铁壁…）时，**走的那个角色会闪一下白光**，
    再叠一层对应属性的特效（攻=火光、防=护盾光、速=旋风、运=星星），并飘出「攻 +3」这样的字；
  - 被削弱（刺耳声之类）换成暗色烟雾 + 紫色飘字；
  - 攻击牌出招时会甩出一道弧光，重击（威力 ≥8）用更大的火光；
  - 命中时按伤害类型给冲击特效，会心一击更大更亮，被护盾挡下则放一圈蓝光；
  - 获得护盾、回血、中毒 / 灼伤 / 虚弱 / 出血各有自己的颜色。
  特效节点播完会自动移除（诊断脚本会核对没有残留）。
- **演出节奏**：战斗是一段一段演的——对手每用一张牌，卡面会摊在它的半场（带「对手使用了」标签），
  然后再做出招动作、再扣血。伤害是**一次一次跳的**，不是回合一开始就结算完。
  嫌慢/嫌快可以在「设置 → 战斗演出速度」里调 **慢 / 标准 / 快**（默认标准），
  也可以直接在网址后面加 `?speed=slow|normal|fast`。
- **战斗布局是自适应算出来的**（`BattleScreen.layoutBattle()`）：
  行走图的缩放由「那一行实际有多高」推出来（不再是写死的倍数 + `38vh`）；
  出牌区的卡面尺寸与位置按当前空白挑位置——**一律优先留在出牌那一侧的半场**
  （玩家的牌就贴在玩家角色卡旁边、敌人的牌贴在敌人那侧），只有外侧实在放不下（< 72px）时
  才挪到右侧日志上方的空白（并按日志的**最大**高度预留空间，免得日志长高压上来）；
  行高 < 128px 时角色卡自动进入紧凑模式（隐藏属性行、缩小头像），信息卡不会溢出到别的行上。
  重算时机：窗口 resize + **ResizeObserver 盯着两条角色行和日志**（行走图换动作、状态图标换行、
  日志长高都会改变可用空间，而窗口尺寸没变）+ 每次摊牌之前。
  验收：`node tools/diag2.mjs "...?dgview=1" 45000 "1180,620"` 换不同窗口尺寸跑，
  看「精灵与顶栏重叠 / 顶部越界 / 出牌区重叠」是否全为 false（诊断脚本会等卡片入场动画落定再量，
  免得量到中间帧误报）。

### 卡组
- **带进战斗的就是你拥有的全部卡牌** —— 没有「挑着不带」这个开关。
  想精简卡组，只能用下面两条路（这也让「卡组厚薄」从随手一勾变成了资源决策）：
  - **商店的「卡牌移除服务」**：11 位商人（12 位里只有好坏星杂货不提供）都有，45~100 金起，
    **不售罄 —— 可以在一家店里连着删，但每删一张这一家的报价就涨一截**（×1.4）。
    买到之后在弹窗里选一张要删的牌；**关掉弹窗不选 = 全额退钱**（以前是钱照扣、卡没删）。
  - **营地的「冥想」**：把一张牌换成随机的高稀有度牌（和「休息回血」二选一）。
- 为什么不再让玩家自由挑选：见踩坑表那条「子弹拳 + 电光一闪」——
  能自由少带的时候，小卡组要么强到离谱（两张 0 费抽 1 互相刷），
  要么在堵住连招之后直接报废，两头都不健康。
- 卡组页（地图上的「卡组」按钮 / `D` 键）现在是**只读的**：
  排序（含特殊效果分组）、卡牌详情、卡牌图鉴、已收集计数都在，
  同一张牌只画一张、角标写 `×N`；它还会说明「怎么改卡组」与当前卡组的构成（伤害牌 / 0 费牌 / 各类效果各几张）。
- 卡组越薄 → 越容易每回合抽到关键牌；越厚 → 每回合能打出的总量上限更高，但抽得散。
- 保存后从下一场战斗开始生效。

### 卡面怎么读
- **全页文字不可选中**（`user-select: none`）：这是个界面不是文档 ——
  对战里拖着鼠标点牌 / 点怪物 / 拉线路时，一不小心就会选中一片文字，
  浏览器给它涂上默认的蓝色高亮，看着像 UI 出了蓝底 bug（用户就是这么被吓到的）。
  需要选字的地方单独放开：表单控件（设置里的滑杆、下拉框）和玩法说明面板（`.help-card`）。
  `img` 也关掉了原生拖影。
- **卡大了**：战斗手牌 186×190（原来 168×148）、卡组列表 148×208（原来 106×150）、
  详情 / 奖励的大卡面 212×272（原来 172×178）。卡面的字号、美术高度、行数上限都是
  `--card-name-fs / --card-text-fs / --card-art-h / --card-clamp` 这几个变量，三档尺寸只改变量。
- **卡名和描述是两个层级**：卡名比同档描述大 4~7px 并且更粗（`font-weight: 800`）——
  手牌 18px vs 12.5px、卡组列表 16px vs 12px、大卡面 21px vs 14px（以前只差 1.5px，看着像同一层信息）。
  名字行高收紧到 1.15，免得把行动点圆圈那行撑高、也把省下的高度留给描述。
  卡名最长 4 个字（电光一闪 / 岩石爆击），三档 + 带勾选圈的卡组页都量过**不会被省略号截掉**。
- **美术改成通栏横幅**：以前美术是左边一竖条（54px），文字只剩三四十像素宽，
  明明是张不小的卡，文案却挤成一列列断行 —— 现在美术占满卡宽、文字吃满整张卡的宽度。
- **摊在场上那张牌是「等比缩小的标准卡面」**：出牌展示区的卡面尺寸由 JS 按可用空白算
  （可能只有 150px 宽，矮窗口下更小），所以卡面内部**所有**尺寸（内边距、字号、美术高度、
  行动点圆圈、底栏、角标）都写成 `calc(原值 * var(--u))`，`--u = 卡宽 ÷ 186` 由
  `layoutPlayZone()` 写进 zone —— 小卡面就是标准卡面的缩小版，排版比例完全一致，
  **任何尺寸下文案都不会被 `-webkit-line-clamp` 截掉**。
- **文案高亮**：数字用砖红加粗、状态词（中毒 / 灼伤 / 虚弱 / 出血）用自己的主题色、
  护盾 / 抽牌 / 行动点 / 销毁 / 反伤 / 破防 / 净化 / 属性增减各有颜色。
  同一套语义**两套配色**：米黄卡面上用深墨，深色界面上用亮色（写反了就是「字看不见」，
  诊断脚本会用亮度值卡这一条）。
- **悬停查词**：卡面上任何带颜色的词（`1 层虚弱`、`护盾`、`销毁`…）鼠标停上去都会弹说明，
  战斗界面、卡组页、详情页都有效（`src/ui/tips.js` 是全站共用的一份）。
  卡面上的指针仍然保持「可点」的样子，不会因为词条变成问号手。
- **手牌叠放是算出来的**：卡面变大之后，写死的 `margin: -14px` 会让七八张手牌顶出屏幕，
  现在由 `fitHand()` 按手牌张数和可用宽度现算（`--hand-overlap`），卡面本身不缩小。

### 成长
- 每场战斗胜利都会**永久提升属性**（野生怪 +3 点预算，精英 +5，首领 +8）。
- 走到首领节点前会自动回复一部分生命；打完首领完全回血。
- 事件、商店、宝箱提供卡牌、道具（药水 / 护符）与属性。
- **商店的摊主是 12 位不同的宝可梦**（沙河马商队、沙铃仙人掌药草摊、大颚蚁挖掘队、石丸子铁匠铺、藤藤蛇花摊、
  强颚鸡母虫废料场、弱丁鱼渔市、好坏星杂货、小箭雀信使、烛光灵灯市、哭哭面具古董商、独剑鞘黑市）。
  每张地图常驻其中 2~4 位，同一个商店节点每次都是同一张脸；**每位商人的货与价都不一样**：
  药草商人一定卖伤药、铁匠铺一定卖护符、黑市货最贵但稀有卡最多、拾荒摊便宜但东西一般。
  商店界面会显示他的**脸图、身份与招呼语**。（选表在 `content/merchants.json`）
- 营地可以「休息回血」或「冥想换卡」，只能二选一（做过一件另一件就锁上，文案也会跟着改）。
  记录存在 run 数据里，中途刷新页面回到同一个营地也不会把机会变回来。

### 界面上的图标
- 卡牌左上角的图标按**效果语义**区分：拳/爪/火焰/地裂/岩崩/风沙/音波/毒瓶/治疗/盾/抽牌/洗牌/增益/削弱/爆发…（不再是「攻击全是剑、治疗全是瓶子」）。

- 全部图标是单色剪影（`currentColor`），颜色跟着所在界面的配色走，所以 6 张地图上会呈现各自的主题色。

## 怎么加内容（内容管线）

**所有内容都写在 `content/` 下的 JSON 里，改完跑三条命令就行**，不需要手写代码：

```powershell
node tools/build-content.mjs    # ① 校验 + 生成到 src/data/*.js 的「GENERATED 区块」
node tools/check-content.mjs    # ② 内容体检：素材在不在、每章敌档是否齐全、图标/特效图、BGM 文件
node tools/check-copy.mjs       # ③ 文案体检：界面文案有没有过期 / 开发口气 / 手抄的公式数字
node tools/bundle.mjs           # ④ 重新打包单文件
```
只想校验、不想改源码时用 `node tools/build-content.mjs --check`（多人同时改内容时用它）。

| 想加什么 | 改哪个文件 | 还要做什么 |
| --- | --- | --- |
| 卡牌 | `content/cards.json` 的 `cards` 数组 | 图标从 `content/icons.json` 注册表的 `ico-*` 里选、特效图只能从 `assets/img/fx/*.png` 里选（体检脚本会拦） |
| 敌人 | `content/enemies.json` 的 `enemies` + 在 `species.json` 里登记物种 | `& tools/fetch-content.ps1` 下载精灵图和头像 |
| 新地图（章节） | `content/biomes.json`（stageOrder 里加键 + 定义配色/`shape`） | 每张地图要有 mob/normal/elite/boss 各至少 1 只，以及 ≥3 个专属事件 |
| 事件 | `content/events/<地图>.json` | 用 `src/core/eventfx.js` 顶部那张 DSL 速查表；文本里的 `{token}` 必须由同选项的效果产出 |
| 图标 | `content/icons.json` 加一条 `{name, source, file, desc, group}` | `source` 写 `pack:<上游组件名>` 或 `local:<assets/img 下的相对路径>`；pack 的先跑 `& tools/fetch-iconpack.ps1` 下素材，然后 `node tools/build-content.mjs` 会把它写进 `src/ui/style.css` 的 GENERATED-ICONS 区块（详见下方「图标是怎么来的」） |
| 商人 | `content/merchants.json` | `slug` 必须是 `species.json` 里的物种（要拿它的头像当脸）、`emotion` 用 `portraits.js` 的小写表情键；每张地图至少要有一位，`node tools/check-content.mjs` 会核对脸图在不在 |
| BGM | `content/bgm.json` | `& tools/fetch-bgm.ps1` 下载 ogg(L) 无缝循环版（缺文件会退回通用曲，不会整条静音） |
| 新物种素材 | `content/species.json` | `& tools/fetch-content.ps1`（幂等，已存在的会跳过；GitHub 连不上时自动换 ghproxy.net / gh-proxy.com / ghfast.top 镜像；最后自动重建 sprites.json） |

管线做了这些事，所以加内容不容易出错：

- **id 唯一性 / 引用完整性**：招式池引用的卡牌、敌人引用的物种、事件引用的道具与卡牌，不存在就直接报错并终止（不会生成半成品）。
- **章节覆盖检查**：`enemyHp`/`enemyAtk` 表长必须等于章节数、难度必须逐章递增、每张地图四档敌人齐全。
- **素材检查**：每个敌人的 Idle/Attack/Hurt 精灵图与 Normal 头像是否真的在磁盘上，卡牌的图标类与特效图是否存在。
- **风格检查**：0 费卡占比过高、招式池平均威力过高、卡面描述没提伤害而效果里有伤害 → 报警告。

为什么要「裁到包围盒」而不是直接用原图：原画布是正面 192²、背面 288² 的固定尺寸，
但**图案占画布多少**每只都不一样（实测 24% ~ 92%，中位数 51%）——
不裁的话，界面得为每一只单独算偏移，而且刺尾虫会看起来像「没画出来」。
裁完之后运行时只需要一个宽高比（`fitArt()`），`canvas` / `box` 两个字段留给诊断脚本核对。

大小差异是**故意保留**的：`artScale = 图案高度÷画布高度 ÷ 0.51`，夹在 0.72~1.24 ——
所以大岩蛇的立绘大约是小虫子的 1.7 倍高，而不是每只都撑满同一个框。

### 图标是怎么来的（Game-Icon-Pack + Kenney）

卡牌的图标以前 86 张只用了 12 种（`ico-warn` 16 张、`ico-sword` 14 张、`ico-flask` 12 张…），
现在换成语义对得上的 41 种（最大共用 5 张），并在状态、属性、地图节点、道具这些原本只有文字的地方补上了图标。
素材来自 [Nieobie/Game-Icon-Pack](https://github.com/Nieobie/game-icon-pack)：**CC0 1.0**，815 个圆角图标，
可以自由使用 / 修改 / 商用（README 里署名是自觉）。

几个关键决定（都是实测出来的，别凭直觉推翻）：

- **仓库里只有 SVG，没有 PNG**（1630 个 = 815 图标 × 带/不带 padding）。取图模板：
  `https://nieobie.github.io/game-icon-pack/svg/no-padding/<category>/<name>.svg`（Pages 直连，不需要镜像）；
  备胎是 `https://ghproxy.net/https://raw.githubusercontent.com/Nieobie/game-icon-pack/main/svg/...`；
  整包一次拿全是 498 KB 的 tar.gz。**github.com 本身在这台机器上直连不通**，脚本走的是镜像链。
- **用 no-padding 版**：padding 版的 viewBox 是 `0 0 10 10`（四周留白），no-padding 紧贴墨迹。
  实测视觉重量 no-padding 30~70% / padding 12~26% / 旧 Kenney 基线 25~39%，
  所以行内 16~20px 的小图标必须用 no-padding，否则会「看着比旁边小一圈」。
- **继续走 CSS mask + `currentColor`**：包里 1630 个 SVG 根节点全是 `fill="currentColor"`、
  没有底色块也没有满幅背景，当 mask 很干净（渲染后不透明像素 17%~85%，不会变成纯色方块）。
  **不要改用 `<img src="assets/...">`** —— `bundle.mjs` 只内联 CSS 里的 `url()`，
  `file://` 下 `<img>` 会被浏览器拦掉，那会直接毁掉单文件包。
- **注册表是唯一数据源**：`content/icons.json`（101 条 = pack 72 + 本地 Kenney 29）→
  `node tools/build-content.mjs` 校验并重写 `src/ui/style.css` 的 `GENERATED-ICONS` 区块（101 条规则）。
  所以「加一个图标」= 改一行 JSON + 跑下载脚本 + build-content，不碰 CSS。
- **类名只能 `[a-z0-9_]`**：上游带连字符的名字要改名（`fire→flame`、`potion→poison`、`medical-kit→heal`、
  `action-points→action_points`、`star-coin→star_coin`…）。否则 `check-icons.mjs` 会把
  `.ico-dragon-breath` 读成 `ico-dragon` 然后误报「未定义」，`.ico-AP` 会被整条丢掉。
- **体积**：SVG 本身很小（46 个才 40.9 KB），但每条 `.ico-*` 规则有 `-webkit-mask-image` 与 `mask-image`
  两条声明，`bundle.mjs` 是按 `url()` 逐处替换的 → 同一张 SVG 会被内联两遍（101 条规则 → 92+ 条 data URI）。

四套字体，按用途分工（都在 style.css 顶部声明 `@font-face`）：

| 变量 | 字体 | 用在哪 |
| --- | --- | --- |
| `--font-body` | `SGHr-Regular-subset.woff2` | 正文：卡面描述、数值、日志、按钮… |
| `--font-bold` | `WenYuanSerifSC-Bold-subset.woff2` | 需要粗体的地方：卡名、商店名、面板标题、遭遇演出里的怪名 |
| `--font-hand` | `YShiWrittenSC-subset.woff2`（写意体 SC） | 手写体：事件旁白、商人对白、结算文案、标题页旁白 |
| ↑ 的补丁层 | `851LakeusNightWriting-patch.woff2`（13 KB） | 写意体缺的那 36 个字（`～ ⓪ ✓ ↔ ≈ －` + 23 个日文汉字）由上一任手写体补上 |
| （兜底） | `LXGWNeoXiHeiPlus.ttf`（8.5 MB） | 上面几套**子集里没有的字**由它接住 |

手写体为什么是「一套主字体 + 一套补丁」：写意体 SC 只有 7977 个码位，游戏用到的 2004 个字里
它缺 36 个，缺的字会直接掉到 LXGW —— 那是套黑体，夹在手写句子里写着「好久没见啦～」，
看着就像「这个字体缺字」。补丁子集只含那几个字，13 KB，接在主字体后面逐字补洞。
（换字体之前用的是 851 远星夜行手写体，它覆盖 2001 个字，现在退居补丁。）

后两套是从仓库根目录那几份**原始字体**裁出来的子集 —— 原始文件加起来 46 MB
（SGHr 3.9 / 文源宋体粗 14.5 / 851 手写 27.5 / 写意体 3.9），直接内联进单文件构建会让
`oasis-game.html` 从 22 MB 涨到 80 MB 以上。裁完之后合计 **1.1 MB**：

```powershell
python -m pip install fonttools brotli     # 只需要一次
node tools/subset-fonts.mjs                # 生成 assets/fonts/*-subset.woff2 + subset-manifest.json
```

裁的依据是「游戏可能显示出来的每一个字」：`content/*.json`、`src/**/*.js`、`index.html`
里出现的所有字符，再补上 ASCII 与常用中文标点。**内容改了（加新卡、新事件）要重跑一次**，
否则新文案里可能有字落到兜底字体上（不会出方块，但两套字体会混着显示）。
这件事已经出过一次事故：改完 46 个事件的旁白没重跑，新写的「呀 / 诶 / 唔 / 哟」整整 39 个字
全落到了兜底黑体上，看起来就像「手写体缺字」（详见下面那条排查记录）。
现在 `subset-fonts.mjs` 会把**内容指纹**写进 `assets/fonts/subset-manifest.json`，
`check-content.mjs` 拿它守门：内容变了而子集没重裁，体检直接红。
原始文件在 `.gitignore` 里（和 Kenney 素材包、Generation 9 的 rar 一样：
只用来生成，运行时读的是 `assets/fonts/` 里的成品）。

打包时字体会内联成 data URI（woff2 按 `font/woff2` 声明 —— 写成 `font/ttf` 浏览器会静默拒收），
所以 `oasis-game.html` 因此长到 ~24 MB。
**如果不想要这么大的单文件**，把 `tools/bundle.mjs` 里「字体内联」那一段删掉，
重新打包就回到 ~12 MB（离线版会用系统字体）。

### 精灵图的朝向行序（踩过的坑）

PMD 精灵图**不是**「一行 = 一个动画」，而是官方文档说的：

> Frames of an animation are ordered **horizontally by sequence**, and **vertically by direction**.
> —— [PMD Sprite Format](https://wiki.pmdo.pmdcollab.org/index.php?title=Tutorial:PMD_Sprite_Format)

也就是**水平方向是帧序列，竖直方向才是朝向**，8 个朝向按固定顺序排列：

| 行 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 朝向 | 下 | 右下 | **右** | 右上 | 上 | 左上 | **左** | 左下 |

我一开始把 8 行当成连续帧全连起来播，结果宝可梦看起来一直在原地转圈。
现在 `src/core/sprites.js` 的 `frameList()` 只取**单一朝向行**，战斗是侧面视角所以
玩家用 `DIR.RIGHT`（第 2 行）、敌人用 `DIR.LEFT`（第 6 行）。

行序不是我猜的 —— 用 SpriteCollab 的 `Offsets.png`（绿点=身体中心、黑点=头）算出
「头相对身体的位置」来判定，`tools/analyze-directions.mjs` 就是干这个的。
另外有些物种没画满 8 个朝向，`frameList()` 会自动退回第一个有内容的行。

#### 为什么是 ogg，以及怎么做到「真的无缝」

上游每首曲子都提供 **mp3** 和 **ogg** 两版，而 ogg 又分三种（站点原话）：

| 版本 | 含义 |
| --- | --- |
| **ogg(L)** | 切れ目のない自然ループ —— **无缝自然循环**（游戏用的就是这个） |
| ogg(R) | 曲子完整放完后再从头重复 |
| ogg | 不循环 |

mp3 版其实不是循环素材，而是**试听用的完整版**：实测 23 首里每一首的时长都差不多是 ogg(L) 的两倍
（平均 130.0s vs 70.5s），而且结尾都有约 **2 秒**的静音（平均尾部静音 2004ms）——
拿它当 BGM 循环，就是每圈都空两秒。ogg(L) 则是上游剪好的无缝素材：平均尾部静音 **0ms**、
平均头部静音 18.7ms，接缝处的采样跳变都小于 3 倍平均步长（也就是末采样接回首采样是连续的）。
换成 ogg 之后体积还从 68MB 降到 31MB。

`tools/verify-bgm-files.mjs` 会把两种格式的这几项指标一起量出来对照（现在 23/23 通过）。

素材换掉只是一半，**播放侧**也得跟得上：

- `<audio loop>` 在多数浏览器上循环时会漏掉一帧（缓冲/解码边界），所以 BGM 现在走
  **WebAudio**：`audio.js` 建好 `AudioContext` 后调用 `music.attach(ctx, master)`，
  `bgm.js` 把整首 ogg `fetch` 下来 `decodeAudioData` 成 `AudioBuffer`，再用 `loop = true`
  的 `BufferSourceNode` 播放 —— 循环点是**采样精确**的。
- 淡入淡出也跟着换成 GainNode 上的自动化曲线（`setValueCurveAtTime` / 线性斜坡），
  不再靠 `setInterval` 逐帧改 `volume`；切歌是「新曲解码好之后才开始交叉淡出」，
  所以解码期间旧曲子一直在响，不会出现空档。
- 解码后的 `AudioBuffer` 一首大约 60 MB，所以只留最近 3 首（LRU 淘汰），
  没解码的压缩数据最多留 6 首；`preload()` 在 WebAudio 通道下只预取压缩数据、不预先解码。
- **循环点是读文件自带的**：这些 ogg(L) 每个都带 `LOOPSTART=` / `LOOPLENGTH=` 注释（RPG Maker / WOLF 那套约定，单位是**采样数**），
  文件结构其实是「前奏 + 循环段」（例如 title.ogg = 4.09 秒前奏 + 102.5 秒循环，加起来正好是文件总长）。
  `bgm.js` 解码前先把这两个值读出来塞进 WebAudio 的 `loopStart/loopEnd` —— 前奏只放一次、到循环尾跳回循环头。
  **如果只写 `loop=true` 不填循环点，等于整首循环，前奏会每圈重放一遍**（听感就是「循环点不对」，实测被听出来了）。
- 没有 WebAudio、或者这首解码失败（例如 Safari 不支持 Vorbis）时，**自动退回 `<audio>` 元素**
  那套老路（仍然挂着 `loop`），所以不会出现「换了格式就整条 BGM 哑掉」。
  （注意：`<audio>` 元素不支持循环点，兜底通道只能整首循环。）

选曲表里写的是**上游 mp3 文件名**（用来查下载地址），真正落盘和代码引用的是
`assets/audio/bgm/<key>.ogg`：上游把 ogg 打包成 zip，里面的文件名是日文标题
（`ontama_rpg_koubouittai_ogg/攻防一体.ogg`），拿它当路径不现实，所以统一改名成 `<key>.ogg`。

zip 的地址也没法从 mp3 名字推出来（是按日文标题的读音命名的，`cross.mp3` →
`ontama_rpg_kurosujinkei_ogg.zip`），所以 `fetch-bgm.ps1` 会**抓一遍站点的分类页**，
把「mp3 名 → ogg 地址」的对照存进 `tools/bgm-ogg-map.json`（603 条）；
加新曲时它只重新抓一遍，平时直接用缓存。

### 踩过的坑（都留了诊断脚本）

| 现象 | 真正的原因 | 修法 |
| --- | --- | --- |
| 战斗中「掉血掉到死、血条完全没动」 | 顶部 HUD 只在**切屏时**才重画，战斗里掉的血从没同步过去 | BattleScreen.syncHud() 每次刷新战斗界面时把血量写回 run 并更新 HUD |

### 平衡是怎么定的

调参过程都留在脚本里，主要结论：

- 现在有 6 章，`enemyHp` / `enemyAtk` / `playerPowerRef` / `stageClearGold` **四张表都必须有 6 个数**
  （`check-content.mjs` 会强制校验长度，还要求难度逐章递增）。
- 目标节奏：**野生怪 3~4.5 回合、精英 4~5 回合、首领 2~4 回合**解决；
  敌方每回合输出约玩家最大生命的 10%~25%（杂兵低、精英与首领高），
  所以不靠治疗大约能撑 4~6 回合。
- **两套测量工具现在用同一个「玩家牌组模型」**（这是几次误判的共同根源）：
  以前的 `tune-curve` / `sweep-curve` 把整副牌都从奖励池里抽（等于假设玩家张张都是龙爪地震），
  牌组比真实情况强一大截，调出来的难度偏难，和 `measure-balance`
  （从起始卡组开始长）能差 20 个百分点。现在两边都是 **起始卡组 + 奖励牌（75% 攻击 / 25% 辅助）**，
  复核时两边的结论已经收敛到 5 个点以内。
- **一次重要的重新校准（「出战卡组 = 全部卡牌」那一版）**：老曲线是在
  `defaultBattleDeck()` 挑出来的 14 张上量的 —— 那个启发式按「威力 ÷ 费用」排序，
  挑出来全是大牌，而真正能每回合打满出牌上限的是便宜牌。带全部卡之后 4~6 章一度 98~100%。
  修法：① **敌攻 ×1.7**（光加血只会把战斗拖成 6~8 回合的磨；「回合数 × 每回合压力」才是难度）；
  ② 用 `tune-curve.mjs --write` 逐格重定 HP；③ 复核时**优先看回合数与每回合压力**
  （它们比单格胜率稳定得多），胜率只要求落在合理区间、整体逐章下降。
- 最新实测（`node tools/measure-balance.mjs 80`，80 场/档，贪婪 AI、不喝药；
  单格胜率仍有 ±10 个点左右的噪声，**看趋势别抠单格**）：

  | 章 | 野生 | 较强 | 精英 | 首领 | 回合（野/精/首） |
  | --- | --- | --- | --- | --- | --- |
  | 1 | 100% | 100% | 65% | 75% | 4.2 / 3.0 / 2.3 |
  | 2 | 98% | 98% | 86% | 90% | 3.9 / 3.9 / 2.8 |
  | 3 | 100% | 98% | 80% | 86% | 3.5 / 4.4 / 3.0 |
  | 4 | 100% | 100% | 83% | 75% | 3.4 / 4.6 / 3.3 |
  | 5 | 98% | 98% | 63% | 76% | 3.5 / 5.0 / 3.5 |
  | 6 | 96% | 99% | 64% | 76% | 4.4 / 5.5 / 3.9 |

  整体是**逐章下降**的，杂兵始终是资源消耗而不是门槛。用 `node tools/tune-curve.mjs --write`
  可以按目标曲线重调一遍（它按「档位 × 章节」二分搜索敌人 HP，目标曲线写在脚本顶部的 `TARGET` 里）。
- **一节战斗现在是 4~5 回合**（以前野生怪只要 3 回合）：因为敌人不再「打两回合就把伤害牌打光、
  后面只会放铁壁」了（见踩坑表），它每回合都真的在输出。想让杂兵更快结束就把 `enemyHp.mob` 整体下调。
- 削弱压力单独有脚本盯：`node tools/measure-debuff.mjs 40` 会打印每个招式池里的削弱牌密度、
  以及「一局里玩家防御最低被压到多少」。加上下限之后，防御最低只到基础值的一半
  （第 1 章 12→8，第 6 章 44→22），再也不会出现负数。
- **小改动要用配对 A/B 量**：`measure-balance.mjs` 每场都靠 `Math.random()` 现拼卡组，
  100 场/档的噪声就有 ±6 个百分点（同一份代码连跑两次，第 6 章精英一次 71%、一次 83%），
  所以「改前跑一次、改后跑一次」的对比基本只能看出大改动。
  `node tools/ab-status.mjs 60` 的做法是：固定 `Math.random` 拼出**同一副卡组**、
  用同一颗种子跑同一场战斗，只切换被考察的那个变量（这里是「剧毒 / 火焰牙 / 热风」的状态层数），
  逐档成对比较。实测 1440 对：旧效果（1/1/1 层）整体 90.1%，照文案补齐（3/2/3 层）88.6%，
  **合计 −1.5 个百分点**，主要吃在精英与首领那几档（敌人也会用这几张牌）。
- **续航**（6 章一趟很长，这几个数值决定玩家能不能真的看到后面的地图）：
  每场战斗后回 12%、营地回 40%、首领前回 60%、药水掉落 68%。
  `node tools/simulate-run.mjs 60` 的机器人（会喝药、会躲精英）平均走到第 2.9 章、通关率 ~3% ——
  机器人打得比人差，真人能到更深，但**通关本身就是稀有事件**（这是刻意保留的设计目标）。
- 另外有一个**战力对齐系数**：如果你的属性落后于章节预期，敌人会相应变弱（最低 ×0.62），
  这样运气差的一局也不会在第三章被直接劝退。
- 敌人的招式池按档位分开（`MOVE_POOLS`，写在 `content/enemies.json`），并且会限制单场平均威力 ——
  否则野生怪一回合抽到三张「地震」就能把你秒了（这个坑真的踩过）。

改完数值后建议跑一遍：

```powershell
node tools/check-balance.mjs     # 数值表
node tools/measure-balance.mjs   # 实测胜率
node tools/simulate-run.mjs 400  # 全流程
```
